## 1. 경기 기록 등록·검토
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

담당자가 내전 묶음, 대결, 세트 단위로 경기 결과를 등록하고 검토하는 기능 영역이다. 결과창 스크린샷을 바탕으로 AI 추출 초안을 검토·수정해 신뢰할 수 있는 기록을 저장하는 범위를 포함한다. 일반 방문자의 기록 수정과 일반 Match-V5 기반 자동 수집은 포함하지 않는다.

**수용 기준:**
```
1. ○ 담당자는 내전 시작일을 기준으로 내전 묶음과 그 아래 대결·세트를 생성할 수 있다.
2. ○ 담당자는 세트마다 업로드 전에 위쪽 팀 진영(기본값: 1세트 1팀 블루, 매 세트 번갈아 규칙)·캡처한 사람의 포지션을 선택하고 결과창을 올린다. 위쪽 팀이 1팀인지 2팀인지는 직전 세트와의 선수 겹침으로 자동 판별한다. 검토 화면은 양 팀을 탑·정글·미드·원딜·서포터 순서로 정렬해 보여주며, 담당자는 틀린 값만 확인·수정해 저장한다.
3. ○ 결과창에서 읽은 세트 지문(날짜 + 경기 시간 + 양 팀 킬 합계 + 양 팀 골드 합계)이 같은 세트가 이미 있으면 새 세트로 중복 등록할 수 없다. 같은 이미지 재업로드는 추출 전에 막는다. 매치 ID는 수집하지 않는다.
4. ○ 저장된 세트는 선수별 실제 포지션, 진영, 승패, 챔피언, 밴 순서를 포함한다.
5. ○ 결과창이 없거나 업로드·AI 추출이 실패하면 담당자는 수동 입력으로 세트를 등록할 수 있으며, 수동 입력에도 지문 중복 검사와 동일한 저장 검증을 적용한다.
6. ○ 저장 검증(선수 10명 중복 없음, 팀별 포지션 5개, 밴 10개, 진영·캡처한 사람의 포지션 필수, 지문 중복 없음 — 지문이 겹치면 예외 없이 등록 불가)에 실패하거나 저장이 실패하면 입력값을 유지한 채 오류 위치를 수정할 수 있다.
```

## 2. 전적·통계 조회
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

일반 방문자가 저장된 내전 기록을 바탕으로 선수별 성적과 과거 경기 정보를 조회하는 기능 영역이다. 개인·챔피언·포지션 단위의 통계와 전체·포지션별 랭킹, 과거 대결 및 밴 기록의 열람을 포함한다. 로그인 기반 개인화와 아이템·룬·오브젝트 통계는 포함하지 않는다.

**수용 기준:**
```
1. ○ 일반 방문자는 로그인 없이 공개된 선수별 승률, 사용 챔피언, 챔피언별 성적을 조회할 수 있다.
2. ○ 일반 방문자는 전체 및 실제 경기 포지션 기준의 랭킹을 조회할 수 있다.
3. ○ 일반 방문자는 과거 대결 기록과 밴 기록을 조회할 수 있다.
4. ○ 일반 방문자는 조회 가능한 기록을 CSV로 내려받을 수 있다. CSV 진입점은 기록 조회를 방해하지 않도록 목록 상단 구석의 작은 버튼으로만 표시한다.
5. ○ 일반 방문자는 경기·밴 기록을 시작일 범위, 선수, 챔피언 조건으로 필터링할 수 있고, 결과가 없으면 빈 결과와 조건 변경 경로가 표시된다.
```

## 3. 담당자 인증·접근 제어
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

담당자가 하나의 운영 계정으로 로그인해 경기 기록과 선수 정보를 관리할 수 있도록 하는 기능 영역이다. 일반 방문자는 로그인 없이 공개 기록을 조회하고, 등록·수정·삭제와 원본 이미지 열람은 담당자에게만 허용한다. 일반 사용자 계정, 디스코드 로그인, 참여자별 편집 권한은 포함하지 않는다.

**수용 기준:**
```
1. ○ 담당자는 ID와 비밀번호로 로그인하고 로그아웃할 수 있다.
2. ○ 로그인하지 않은 방문자는 공개 기록을 조회할 수 있지만 운영 화면에 접근할 수 없다.
3. ○ 담당자만 선수·별칭·내전·대결·세트 기록을 생성·수정·삭제할 수 있다.
4. ○ 원본 결과창 이미지는 담당자만 열람할 수 있다.
```

## 4. 선수·별칭 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

담당자가 내전 참여 선수를 고유한 선수 ID와 표시 이름으로 관리하고, 결과창에 나타난 닉네임을 해당 선수에게 연결하는 기능 영역이다. 닉네임 변경·부계정·잘린 닉네임으로 인한 기록 분산을 막기 위해 별칭 이력을 유지한다. 일반 방문자가 선수 식별 정보를 변경하는 범위는 포함하지 않는다.

**수용 기준:**
```
1. ○ 담당자는 선수를 생성하고 표시 이름과 주력 포지션을 수정할 수 있다. 선수 비활성화는 이번 범위에서 제외한다.
2. ○ 담당자는 한 선수에게 여러 닉네임 별칭을 등록하고 관리할 수 있다.
3. ○ AI가 추출한 닉네임이 기존 선수와 일치하면 자동 연결되고, 비슷한 후보가 있으면 담당자가 고른다. 처음 보는 닉네임은 미등록 선수로 자동 생성되어 게임 닉네임으로 표시되며, 담당자가 나중에 등록(실명 입력)하면 기존 기록을 유지한 채 실명으로 바뀐다. 잘린 닉네임은 보이는 부분이 등록된 닉네임 앞부분과 약 70% 이상 일치하면 자동 연결되고, 일치하는 선수가 없을 때만 전체 닉네임을 입력해 미등록 선수로 저장한다.
4. ○ 별칭이 변경되어도 기존에 저장된 세트 기록은 동일한 선수 ID에 연결되어 유지된다.
```

## 5. 기록 공개·운영 관리
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중

저장된 기록이 언제부터 공개되는지와 원본 이미지 등 운영 데이터의 접근 범위를 정하는 기능 영역이다. 저장된 세트는 별도 공개 단계 없이 즉시 공개되며, 원본 이미지와 운영 데이터는 담당자 관리 범위로 제한한다. 다중 그룹 운영과 일반 사용자별 공개 범위 설정은 포함하지 않는다.

**수용 기준:**
```
1. ○ 담당자가 저장한 세트는 별도 공개 단계 없이 즉시 공개 조회와 통계에 반영된다.
2. ○ 검토 중이거나 저장되지 않은 AI 추출 초안은 일반 방문자 조회와 통계에 표시되지 않는다.
3. ○ 원본 이미지와 공개 조회용 경기 데이터는 서로 다른 접근 권한으로 관리된다.
```

> 백업·복원은 화면 기능이 아니라 운영 작업으로 처리한다(관리형 DB 자동 백업, 정기 복원 테스트, 운영 일지 기록).

## 6. 대결 진행 규칙 (점수·피어리스·팀 교환)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

대결 안에서 1팀·2팀의 세트 스코어와 누적 피어리스 제한을 이어가고, 같은 라인 선수 교환과 초기화를 실제 운영 방식대로 기록하는 기능 영역이다. 게임 클라이언트에서 피어리스를 강제하는 기능은 포함하지 않는다.

**수용 기준:**
```
1. ○ 대결 상세에는 1팀·2팀 세트 스코어, 세트 목록, 현재 피어리스 제한 챔피언이 표시된다. 블루·레드는 세트마다 번갈아 바뀌는 진영으로 1팀·2팀과 따로 기록된다. 1세트는 1팀 블루로 시작한다.
2. ○ 세트가 저장되면 그 세트의 픽 챔피언 10개가 같은 대결의 이후 세트에 양 팀 공통 제한으로 누적된다.
3. ○ 담당자는 같은 라인 선수 교환을 기록할 수 있고, 교환 후에도 기존 점수·피어리스 제한·이전 세트의 개인 기록은 유지된다.
4. ○ 담당자가 피어리스·점수 초기화를 하면 기존 대결 기록은 보존되고, 0:0·제한 없음 상태의 새 대결이 생성된다.
5. ○ 저장하려는 세트에 피어리스 제한 챔피언이 있으면 인식 오류 또는 초기화 누락 가능성을 경고한다.
```

## 7. 기록 수정·삭제·복구·이력
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중

담당자가 저장된 세트의 오류를 바로잡고, 실수로 지운 기록을 되살리며, 변경 내역을 추적하는 기능 영역이다. 일반 방문자에게 변경 이력을 공개하는 범위는 포함하지 않는다.

**수용 기준:**
```
1. ○ 담당자는 저장된 세트의 선수 연결·진영·실제 포지션·승패·챔피언·K/D/A·CS·골드·밴·날짜·경기 시간을 수정할 수 있고, 지문에 쓰이는 값을 수정하면 중복을 다시 검사한다.
2. ○ 담당자는 세트를 삭제할 수 있으며, 삭제된 세트는 공개 조회·통계·랭킹·CSV에서 제외되고 삭제 목록에서 복구할 수 있다.
3. ○ 수정·삭제·복구 후 팀 점수, 피어리스 제한, 대결 결과, 개인 통계, 랭킹, CSV가 현재 유효 기록 기준으로 갱신된다.
4. ○ 수정·삭제·복구 내역은 세트별 변경 이력으로 남고 담당자만 조회할 수 있다.
```
