# ADR 014. 경기 시간 "모름"을 허용하고 이미지 없이 세트를 가져온다

- 상태: 확정 (M5.5, 2026-10-21)
- 관련: ADR 004(세트 지문), ADR 006(유효 세트 UNIQUE), 코드 `registration/SetRegistrationService.importSet`, `tools/artifact-import/import-matches.js`

## 배경

친구 아티팩트에만 있는 2026-10-15 경기 3판을 운영 DB에 넣어야 한다. 그 기록에는 경기 시간이 없고 결과창 이미지도 없다(클라이언트 기록 소실). 기존 저장 경로는 추출 작업(이미지)과 경기 시간(`mm:ss`)을 필수로 요구하고, `game_set.duration_sec`은 NOT NULL이다.

## 결정

- 마이그레이션 V6: `duration_sec`을 NULL 허용, CHECK는 `duration_sec IS NULL OR duration_sec > 0`. `image_hash`/`image_key`는 이미 NULL 허용이라 변경 없음.
- 지문(ADR 004)은 시간이 없으면 시간 자리를 `?`로 둔다: `2026-10-15|?|8:29846|26:39852`. 숫자 형식과 절대 겹치지 않아 기존 지문 문자열은 바뀌지 않고 기존 행 재계산도 필요 없다.
- 담당자 전용 `POST /api/admin/duels/{duelId}/sets/import`(CSRF 필요): 선수는 확정된 playerId, 진영(BLUE/RED) 기준 본문. 서버가 다음 세트 번호, 1팀/2팀 판정, 검증(10명·포지션·밴·카탈로그·피어리스·지문 중복 409)을 기존 `SetEvaluator`로 그대로 수행한다. 팀 합계는 선수 행 합으로 채운다.
- 공개 API의 `durationSec`은 null 가능, 화면은 "—", CSV는 빈 칸. 결과창 등록 경로는 여전히 경기 시간이 필수다.
- 도구 `import-matches.js`가 아티팩트 경기를 변환해 이 API로 넣는다.

## 대안

| 대안 | 버린 이유 |
|---|---|
| 경기 시간을 임의 값(예: 1초)으로 저장 | 거짓 데이터가 평균 시간 등 통계에 섞이고, 나중에 구분할 수 없다 |
| 지문에서 시간을 빼기 | 기존 지문 형식이 바뀌어 전체 재계산·충돌 위험이 생긴다 |
| 가짜 추출 작업 행을 만들어 기존 저장 경로 사용 | 이미지가 없는 작업이 추출 테이블을 오염시키고 1:1 제약을 억지로 맞춰야 한다 |
| DB에 직접 INSERT | 팀 판정·피어리스·중복 검증을 우회한다 |

## 결과

- 시간을 모르는 세트끼리는 날짜와 두 팀의 킬·골드 합계가 모두 같을 때만 중복으로 본다(시간 정보가 없는 만큼 중복 판별이 약하다).
- 시간 평균 같은 통계를 새로 만들 때는 null을 제외해야 한다(현재 시간을 쓰는 통계는 없다).
- 가져오기 도구를 같은 날짜로 재실행하면 새 대결이 추가되고, 첫 경기가 지문 중복(409)으로 막혀 중단된다.
