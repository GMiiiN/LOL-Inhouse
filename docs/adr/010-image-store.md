# ADR 010. 결과창 원본 이미지는 해시를 키로 저장소 인터페이스에 둔다 (M4 로컬, M7 S3)

- 상태: 확정 (M4, 2026-10-20)
- 관련: `docs/design/m4-design.md` D7·D8·§2.3, [ADR 002 비밀값과 샘플](002-secrets-and-samples.md), 코드 `ingest/image/*`

## 배경

결과창 원본은 추출과 나중의 확인(세트 상세에서 원본 보기)에 필요하다. 이미지에는 친구들의 게임 닉네임이 보인다. 지금은 로컬에서만 돌고, 배포(M7)에서는 AWS S3를 쓸 예정이다.

## 결정

- `ImageStore` 인터페이스(`put(hash, mime, bytes)`, `get(key)`)를 두고 M4는 `LocalImageStore`로 구현한다. 위치는 `${IMAGE_STORE_DIR:../data/images}`, 키는 `{hash 앞 2자}/{sha256}.{png|jpg}`.
- 같은 이미지는 같은 키라 다시 써도 무해하다(멱등). 임시 파일에 쓴 뒤 옮겨서 반쯤 쓴 파일이 남지 않게 하고, 키 형식 검사와 경로 정규화로 저장소 밖으로 벗어나지 못하게 한다.
- 업로드는 10MB, PNG/JPEG, 4096×4096 이하만 받는다(크기는 디코딩 전에 먼저 읽어 압축 폭탄을 막는다).
- 같은 해시의 유효 세트가 있으면 409 `DUPLICATE_IMAGE`로 1차 차단한다(최종 중복 방지는 세트 지문, ADR 004·006).
- `data/`는 `.gitignore`로 저장소에서 뺀다.

## 대안

- **DB BLOB**: 백업이 커지고 DB 부하가 늘어난다.
- **처음부터 S3**: 로컬 개발·테스트에 AWS 계정이 필요해진다.

## 결과

- M7에서 같은 키 형식으로 S3 구현만 바꿔 끼운다.
- 저장하지 않은 작업의 이미지는 지금은 계속 쌓인다. M7에서 S3 수명 주기 규칙으로 7일 뒤 지운다(2026-10-17 결정).
