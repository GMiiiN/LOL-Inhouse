# ADR 012. 라인 티어는 현재 값과 "마지막 변경"만 저장하고, 회차·변동 이력은 두지 않는다

- 상태: 확정 (M4.5, 2026-10-21)
- 관련: `docs/design/m45-design.md` §10 Q2·§11, `V4__tier_team_maker.sql`(`player_lane_tier`), 코드 `domain/tier/*`, `tier/*`

## 배경

친구 아티팩트는 티어를 고칠 때 "회차"를 두고, 가장 최근 회차에 오르거나 내린 라인에 ▲▼를 보여 줬다. 회차는 주인이 "공유하기"를 누른 단위였다. 우리는 저장하는 즉시 모두에게 보이므로 그 의미를 그대로 옮기기 어렵고, 설계 초안의 "회차 시작 버튼 + 변동 로그"는 처음 입력 후 회차를 넘길 수 없는 문제와 동시성 문제를 낳았다(Codex 설계 리뷰 P1).

사용자 결정(2026-10-20): "티어 변동은 계속 유기적으로 할 것이라 따로 기록하지 않고, 한번 설정하면 다시 설정하기 전까지 유지한다."

## 결정

- `player_lane_tier`(선수 × 라인 1행)에 현재 티어(1~6)·우열(HIGH/MID/LOW)과 **마지막 변경**(`last_change_direction` UP/DOWN, `last_change_from_tier`, `last_change_from_sub`)만 둔다. 회차 테이블과 변동 이력 테이블은 만들지 않는다.
- 값이 바뀌면 `rank = (7 - tier) × 3 + 우열 보너스`로 방향을 정해 마지막 변경을 덮어쓴다. 같은 값으로 저장하거나 새 라인을 추가하면 마지막 변경은 그대로(새 라인은 없음), 라인을 지우면 행을 지운다.
- ▲▼는 다음에 그 라인을 바꿀 때까지 계속 보인다.
- 가져오기 도구는 `recordChange: false`로 보내 ▲▼를 남기지 않는다.

## 대안

- **회차 + 변동 로그**: 아티팩트와 가장 비슷하지만 운영(회차 넘기기)이 필요하고 처음 입력·동시성 문제가 있다.
- **날짜가 바뀌면 자동 회차**: 버튼은 없지만 하루에 두 번 고치면 묶이고, 내전 다음 날 고치면 갈린다.

## 결과

- 단순하고, 운영 동작이 필요 없다. "언제 얼마나 바뀌었는지"의 역사는 남지 않는다(필요해지면 변동 로그를 새로 추가).
