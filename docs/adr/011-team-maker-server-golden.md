# ADR 011. 팀 짜기 계산은 서버에서 하고, 친구 아티팩트와 같은 결과를 골든 테스트로 보장한다

- 상태: 확정 (M4.5, 2026-10-21)
- 관련: `docs/design/m45-design.md` D1~D3·§1·§7.1·§10~§12, 코드 `domain/team/TeamMaker`, `teammaker/*`, `tools/team-maker-golden/*`

## 배경

친구가 만든 Claude 아티팩트("League of Legends Team Maker")의 자동 팀 짜기를 그대로 옮겨야 한다. 사용자는 "같은 10명·같은 점수표면 아티팩트와 같은 팀 후보가 나오는 것"을 기대한다. 아티팩트는 브라우저 JavaScript로 계산했고, 동점 처리가 참가자 순서·순열 순서·정렬 안정성에 기대고 있어서 다시 구현하면 결과가 미묘하게 달라지기 쉽다.

## 결정

- 계산(자동 126분할 × 라인 배정, 수동 16가지, 같은 팀 조건, 비용 `diff × 3 + gap`, 동점 시 총점 큰 쪽 → 먼저 찾은 것, 안정 정렬 후 상위 4개)은 **서버의 순수 Java 도메인**에서 한다. 점수 공식은 서버에만 둔다.
- 친구의 계산 함수를 **고치지 않고** `tools/team-maker-golden/reference.js`로 옮기고(친구 허락), 가상 선수로 만든 410개 시나리오(기존 350 + 라인 고정 60)의 결과를 `golden-v2.json`으로 저장한다(app.js SHA-256 `f7194a45…57dd94`, 2026-10-21 새 버전 반영). Java 테스트가 결과 목록 전체(순서·슬롯·합계·차이)를 **완전 일치**로 비교한다.
- 후보별 좌우 무작위 교체는 도메인 밖(서비스, 주입한 난수)에서 해서 도메인은 결정적으로 테스트한다.
- 결과를 받은 뒤의 자리 교체·진영 바꾸기·코인토스는 화면에서 하고, 점수는 서버가 함께 보낸 점수표(`scoreMatrix`)에서 찾는다.
- 공개 계산 API에는 남용 방지(동시 2개, 주소별 분당 30회, 같은 팀 조건 5쌍)를 둔다.

## 원본과 의도적으로 다른 점

- 교체 후 총점은 `blueSum + redSum`으로 다시 계산한다(원본은 갱신하지 않는 결함).
- 참가자가 아닌 사람이 낀 같은 팀 조건은 서버가 400으로 먼저 거절한다(원본은 잘못된 결과·NaN).
- 수동 모드에서 그 라인 티어가 없는 사람도 고를 수 있고, 담당자가 입력한 티어 단계 차이(tierGaps)로 그 사람의 추정 티어를 정해 계산한다(2026-10-22 사용자 결정, 원래는 400 거절). 자동 모드의 라인 고정 대체 점수는 그대로다.
- 점수는 정수만 받는다.
- 코인토스는 블루 칸을 A팀으로 둔다(대결 규칙 "1세트 블루 = A팀").

## 대안

- **프런트(TypeScript)로 옮기기**: 원본과 같은 런타임이라 대조는 쉽지만, 규칙 기준이 브라우저 두 곳(캐시된 티어)으로 나뉘고 프로젝트의 도메인 TDD 원칙에서 벗어난다.

## 결과

- 정상 입력에서 아티팩트와 같은 결과(350/350)를 테스트로 보장한다. 최악 계산은 약 0.1초.
- 원본 규칙을 바꾸고 싶으면 `reference.js`가 아니라 우리 도메인을 바꾸고, 골든을 다시 만들 때 차이를 이 ADR에 적는다.
