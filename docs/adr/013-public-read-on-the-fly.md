# ADR 013. 공개 조회는 저장값 없이 조회 때마다 계산하고, 원본 결과창은 방문자에게 보이지 않는다

- 상태: 확정 (M5, 2026-10-21)
- 관련: `docs/design/m5-design.md` §0·§2·§3·§5·§9·§10, 코드 `record/*`, `record/export/*`, `stats/*`, `domain/stats/*`

## 배경

M5는 로그인 없이 보는 화면(홈·내전 기록·대결/세트 상세·선수·랭킹·챔피언 통계)과 CSV 내보내기를 만든다. 통계(승률·KDA·참여율·랭킹·픽밴)를 미리 집계해 저장할지, 볼 때마다 계산할지 정해야 한다. 또 결과창 원본에는 친구 닉네임이 그대로 찍혀 있어 공개 범위를 정해야 한다.

## 결정

- **조회 시 계산**: 통계 테이블·캐시를 두지 않는다. `RecordReader`가 JPQL 생성자 프로젝션으로 세트·선수·밴·이름을 IN 일괄 로딩하고(고정 쿼리 수), M2 도메인(`domain/stats`)이 메모리에서 계산한다. 스키마 변경은 없다.
- **세트 화면 조립은 한 곳**: `SetViewAssembler.assemble(setIds)`가 기록·대결 상세·세트 상세·홈·프로필 최근 경기를 모두 만든다. 피어리스 체인은 표시 필터로 줄이지 않고 같은 묶음의 전체 유효 세트로 계산한다.
- **필터 하나**: 기록 화면과 CSV가 같은 `RecordFilter`(기간·선수·챔피언·`championScope` ANY/PLAYER_PICK)를 쓴다. 대결 점수는 필터와 무관하게 전체 값이다.
- **공개 범위**: 응답에는 `displayName`만 나간다. 실명 원본·게임 닉네임 목록·별칭·요주 표시·이미지 키·지문은 내보내지 않고, 테스트가 금지 키를 검사한다. 원본 결과창은 담당자 전용 `GET /api/admin/sets/{id}/image`로만 본다.
- **CSV**: 파일 하나(세트×선수 행, 밴 10열 반복), UTF-8 BOM·CRLF·RFC 4180, 문자열 셀 수식 방어(`= + - @`, 전각, 탭·CR·LF 앞에 `'`).

## 대안

- **집계 테이블(저장 시 갱신)**: 조회는 빠르지만 M6 수정·삭제·복구 때마다 재계산 경로가 생기고 정합성 버그가 생기기 쉽다. 연 약 830세트 규모에는 필요 없다.
- **애플리케이션 캐시**: 같은 이유로 무효화 규칙만 늘어난다. 느려지면 그때 측정 후 도입한다.
- **원본 이미지 공개**: 확인에는 편하지만 친구 닉네임이 그대로 노출된다.

## 결과

- 수정·삭제가 들어와도 다음 조회에 바로 반영된다. 테스트는 세트 3개와 30개에서 쿼리 수가 같은지로 N+1을 막는다.
- 데이터가 수만 세트로 커지면 기간 전체를 메모리로 읽는 부분(프로필·기록 필터)을 다시 봐야 한다.
